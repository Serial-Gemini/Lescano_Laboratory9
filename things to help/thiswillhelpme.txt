3. Part A — Set up your development environment
The PDF estimates two to three hours for the laboratory. Laboratory 1 Getting Started with React Native (Expo + Tailwind) - Updated (1).pdf


Since you're using Windows 10 and have previously preferred putting development files on your D: drive, you can keep the project there to avoid unnecessarily filling your C: drive. 
Step A1. Install Android Studio
1. Open the official Android Studio website.
2. Download and install Android Studio.
3. Choose the Standard installation.
4. Open Android Studio and let it download the Android SDK and required components.
5. Find the SDK location in Android Studio's Settings under Languages & Frameworks → Android SDK.
The Android SDK contains the tools and platform files needed to run and develop Android applications. You need it even though you will initially write JavaScript rather than Java or Kotlin.

The usual Windows SDK path is:
C:\Users\<your-name>\AppData\Local\Android\Sdk


Replace <your-name> with your Windows account folder name. Do not type the angle brackets literally.
Step A2. Configure the Android environment variables
Windows needs to know where Android's command-line tools are located.
1. Press the Windows key.
2. Search for Edit environment variables for your account.
3. Open it.
4. Under User variables, click New.
5. Enter these values:
Field	Value
Variable name	ANDROID_HOME
Variable value	Your actual Android SDK path

6. Find the Path variable under User variables and click Edit.
7. Add a new entry:
%ANDROID_HOME%\platform-tools


8. Save your changes and close your terminal windows. Open a new Command Prompt or PowerShell window.

Now run:
adb --version


What does this command do?
- adb stands for Android Debug Bridge.
- It is a command-line tool used to communicate with Android devices and emulators.
- --version asks it to print its installed version.
Expected result: version information appears. If Windows says that adb is not recognized, recheck the SDK path and Path entry.
Step A3. Create an Android emulator
1. Open Android Studio.
2. Go to Device Manager.
3. Click Create Device.
4. Choose a phone, such as a Pixel device.
5. Select an Android system image with API 34 or newer, as specified in the PDF.
6. Download the image if needed.
7. Finish creating the device.
8. Click its Play button and wait for the Android home screen.
An emulator is effectively a virtual Android phone. You will use it to view your application without needing to scan a QR code with a physical phone.

If it will not start, check that CPU virtualization is enabled in your BIOS. The lab also recommends enabling Windows Hypervisor Platform if required.
Step A4. Optional: Use your physical phone
You can skip this step because the lab uses an emulator.

If you want to use a phone instead, install Expo Go from the official app store, connect the phone and computer to the same Wi-Fi network, and scan the QR code that Expo displays later.

The PDF warns that its Expo SDK 57 project may not work with the newer Expo Go version targeting SDK 58. The emulator is therefore the safer choice for following this particular lab. Laboratory 1 Getting Started with React Native (Expo + Tailwind) - Updated (1).pdf

5. Part C — Build your first Hello World app
Now you will replace the starter screen with a simple React Native interface.
File: App.js
Open App.js, delete its existing contents, and use this complete code:

import { View, Text } from 'react-native';

export default function App() {
  return (
    <View
      style={{
        flex: 1,
        alignItems: 'center',
        justifyContent: 'center',
      }}
    >
      <Text>Hello, World!</Text>
    </View>
  );
}



Save the file. The emulator should update automatically through Fast Refresh.
Understand every line
Line 1 — Import the components
import { View, Text } from 'react-native';


- import makes code from another module available in this file.
- { View, Text } selects two named exports from the React Native package.
- View is a container that holds and arranges other components.
- Text displays text.
- 'react-native' identifies the package providing them.
The curly braces here mean that you are importing named exports. They are not the same as the curly braces you will use for JavaScript expressions inside JSX.

Line 3 — Define the app component
export default function App() {


- function App() defines a JavaScript function named App.
- In React, this function is a component because it returns JSX describing the interface.
- export default makes this the file's primary export so the application entry point can load it.
Line 4 — Begin returning the interface
return (


The return statement tells the function what to produce. The parentheses allow the JSX to span several lines and make the layout easier to read.

Lines 5–12 — Create and style the container
<View
  style={{
    flex: 1,
    alignItems: 'center',
    justifyContent: 'center',
  }}
>


- View creates the container.
- style accepts a JavaScript object of React Native style properties.
- The first pair of braces opens the JSX expression.
- The second pair creates the JavaScript object.
Now the three important style properties:
Property	Explanation
flex: 1	Allows the container to occupy available space in its parent.
alignItems: 'center'	Centers children across the cross-axis. With the default column layout, this is horizontal centering.
justifyContent: 'center'	Centers children along the main axis. With the default column layout, this is vertical centering.

Together, these settings center the greeting in the available screen area.

Line 13 — Display the greeting
<Text>Hello, World!</Text>


The Text component renders the words on the screen. The text is placed between its opening and closing tags.

Lines 14–17 — Close the components and function
</View>
);
}


- </View> closes the container.
- ); finishes the returned JSX expression.
- } closes the App function.
The opening and closing tags must match. If you forget one, you may get a syntax error.
Why can't you write the text directly inside View?
This will cause an error in React Native:
<View>Hello, World!</View>


The reason is that React Native requires text content to be rendered inside a Text component. Use this instead:
<View>
  <Text>Hello, World!</Text>
</View>


This is one of the most important differences between React Native and ordinary HTML.
Checkpoint
Before proceeding, make sure:
- [x] The emulator displays Hello, World!.
- [x] The greeting appears centered.
- [x] The terminal has no red build error.
- [x] You understand why View and Text are imported.
6. Part D — Install and configure Tailwind with NativeWind
In Part C, you styled the screen using JavaScript style properties. Now you'll use Tailwind classes instead.

For example, instead of writing:
<View style={{ flex: 1, backgroundColor: '#4f46e5' }}>


you'll be able to write:
<View className="flex-1 bg-indigo-600">


The second version is shorter, and each class describes a specific styling rule.

Important: Follow the PDF's version combination. It specifies NativeWind 4.2.7 and Tailwind CSS 3.4. Do not substitute NativeWind v5 into this configuration. Laboratory 1 Getting Started with React Native (Expo + Tailwind) - Updated (1).pdf

Step D1. Stop the server and install the packages
If Expo is running, focus its terminal and press Ctrl + C.

Run the following commands one at a time, from inside the lab1-hello-rn folder.

First:
npm install nativewind@4.2.7


This installs NativeWind at the specified version.

Second:
npm install --save-dev tailwindcss@^3.4.17 prettier-plugin-tailwindcss@^0.5.11 babel-preset-expo


This installs development dependencies:
- tailwindcss@^3.4.17: the Tailwind CSS v3 toolchain.
- prettier-plugin-tailwindcss@^0.5.11: a Prettier plugin that can sort Tailwind classes when formatting code.
- babel-preset-expo: the Babel preset used for Expo's JavaScript transformation.
The --save-dev flag records these packages as development dependencies in package.json.

Third:
npx expo install react-native-reanimated react-native-worklets react-native-safe-area-context


Why use npx expo install here instead of npm install? Expo can select compatible versions of packages that integrate with your particular Expo SDK. These libraries provide animation-related functionality and safe-area components that you will need for the project configuration and layout.

Fourth:
npx expo install --check


This checks whether installed packages match the versions expected by the Expo SDK. Follow any fixes it offers that are appropriate for this project.

Do not run npm audit fix --force just because npm reports vulnerabilities. The laboratory specifically warns that forcing dependency upgrades can break this version-sensitive setup.
Step D2. Create tailwind.config.js
Run:
npx tailwindcss init


This generates the Tailwind configuration file.

File: tailwind.config.js

Replace its contents with:

/** @type {import('tailwindcss').Config} */
module.exports = {
  content: ['./App.{js,jsx,ts,tsx}', './components/**/*.{js,jsx,ts,tsx}'],
  presets: [require('nativewind/preset')],
  theme: {
    extend: {},
  },
  plugins: [],
};



Let's explain every section.

/** @type {import('tailwindcss').Config} */

This is a JSDoc type annotation. It helps editors understand that the exported object is intended to be a Tailwind configuration. It is not required JavaScript logic at runtime.

module.exports = { ... }

This exports the configuration using CommonJS syntax so Tailwind can load it.

content: [...]
content: ['./App.{js,jsx,ts,tsx}', './components/**/*.{js,jsx,ts,tsx}'],


This tells Tailwind which files to scan for utility classes.
- ./App... covers your main app file.
- ./components/... covers JavaScript and TypeScript files inside the components directory.
- * matches names at a particular level.
- **/* covers files in nested directories as well.
- {js,jsx,ts,tsx} matches the listed file extensions.
Why does this matter? If Tailwind does not scan a file, it may not generate the styles used by the classes in that file.

presets
presets: [require('nativewind/preset')],


This loads NativeWind's Tailwind preset, which supplies the configuration needed for NativeWind's React Native styling.

theme
theme: {
  extend: {},
},


This is where you can extend Tailwind's default design system with custom colors, spacing values, fonts, and other theme settings. For this lab, it remains empty.

plugins
plugins: [],


This is an array for additional Tailwind plugins. No additional plugins are needed here.
Step D3. Create global.css
In VS Code, right-click the project root and select New File. Name it:
global.css


Make sure it is beside App.js, not inside components.

File: global.css
@tailwind base;
@tailwind components;
@tailwind utilities;


These three directives tell Tailwind to include its base styles, component-layer styles, and utility classes in the generated stylesheet.

NativeWind needs this stylesheet to connect your Tailwind configuration to the styling system. Later, you'll import this file once in App.js.
Step D4. Create babel.config.js
Create another file in the project root named babel.config.js.

File: babel.config.js

module.exports = function (api) {
  api.cache(true);

  return {
    presets: [
      ['babel-preset-expo', { jsxImportSource: 'nativewind' }],
      'nativewind/babel',
    ],
  };
};



Explanation:
- module.exports = function (api) exports a function that Babel uses to obtain its configuration.
- api.cache(true) tells Babel it can cache this configuration rather than repeatedly recalculating it.
- return provides the configuration object.
- presets lists the transformations Babel should use.
- babel-preset-expo supplies Expo's Babel configuration.
- { jsxImportSource: 'nativewind' } configures the JSX runtime source for NativeWind.
- 'nativewind/babel' adds NativeWind's Babel integration.
Babel transforms your JavaScript and JSX into code the application can execute. This configuration is important because the app must understand your JSX and NativeWind styling.
Step D5. Create metro.config.js
Create a file named metro.config.js in the project root.

File: metro.config.js

const { getDefaultConfig } = require('expo/metro-config');
const { withNativeWind } = require('nativewind/metro');

const config = getDefaultConfig(__dirname);

module.exports = withNativeWind(config, {
  input: './global.css',
});



Explanation:

getDefaultConfig imports Expo's default Metro configuration generator.

withNativeWind imports a helper that integrates NativeWind into Metro.
const config = getDefaultConfig(__dirname);


- const declares a variable that cannot be reassigned.
- __dirname represents the directory containing this configuration file.
- The statement creates the default Metro configuration for your project.
module.exports = withNativeWind(config, {
  input: './global.css',
});


This exports the Metro configuration after adding NativeWind's integration. The input property identifies the CSS file that NativeWind should process.

The three configuration files have different jobs:
File	Main responsibility
tailwind.config.js	Which files to scan and which Tailwind preset to use.
babel.config.js	How JavaScript and JSX are transformed for NativeWind.
metro.config.js	How Metro integrates and processes NativeWind and the CSS input.

Do not confuse these files or paste all three configurations into a single file.

This is an example of the relevant structure, not necessarily the complete contents of your file.

Let's break this down.

Import
import { View, Text } from 'react-native';


This file uses a View to create the bar and Text to display the title and menu symbol. It does not need to import Pressable because the menu is decorative in this lab.

Function and export
export default function TopBar() {

<View className="flex-row items-center justify-between bg-indigo-600 px-4 py-4">

Step E5. Assemble everything in App.js
Now open the root App.js and replace the Tailwind test screen from Part D.

File: App.js

import './global.css';

import {
  Text,
  Pressable,
  ScrollView,
} from 'react-native';

import {
  SafeAreaProvider,
  SafeAreaView,
} from 'react-native-safe-area-context';

import TopBar from './components/TopBar';
import NavBar from './components/NavBar';

export default function App() {
  return (
    <SafeAreaProvider>
      <SafeAreaView className="flex-1 bg-slate-50">
        <TopBar />

        <ScrollView
          className="flex-1"
          contentContainerClassName="p-4"
        >
          <Text className="text-3xl font-bold text-slate-800">
            Hello, World!
          </Text>

          <Text className="mt-2 text-base text-slate-600">
            Welcome to React Native. This is my first mobile
            application built with Expo and NativeWind.
          </Text>

          <Pressable className="mt-6 items-center rounded-xl bg-indigo-600 py-3">
            <Text className="font-bold text-white">
              Get Started
            </Text>
          </Pressable>

          <Pressable className="mt-3 items-center rounded-xl border border-indigo-600 py-3">
            <Text className="font-bold text-indigo-600">
              Learn More
            </Text>
          </Pressable>
        </ScrollView>

        <NavBar />
      </SafeAreaView>
    </SafeAreaProvider>
  );
}



This is the main file, so let's explain its structure carefully.
1. Import the global stylesheet
import './global.css';


This loads the CSS entry point for NativeWind. Keep it in App.js only, as directed by the lab.
2. Import React Native components
import {
  Text,
  Pressable,
  ScrollView,
} from 'react-native';


- Text displays the heading, paragraph, and button labels.
- Pressable creates the two buttons.
- ScrollView makes the central content scrollable if it becomes taller than the available screen.
App.js doesn't directly use View, so it doesn't need to import it.
3. Import the safe-area components
import {
  SafeAreaProvider,
  SafeAreaView,
} from 'react-native-safe-area-context';


SafeAreaProvider provides the safe-area context used by safe-area-aware components.

SafeAreaView helps keep the content within the usable screen area, away from areas such as the status bar and camera notch.

The laboratory asks you to use both to create the outer layout.
4. Import your own components
import TopBar from './components/TopBar';
import NavBar from './components/NavBar';


These imports connect the two component files you just created to the main application.

The component files export their functions, and App.js imports those functions. This is how you reuse components without copying their markup into App.js.
5. Define the app and safe-area layout
<SafeAreaProvider>
  <SafeAreaView className="flex-1 bg-slate-50">


The provider wraps the application content, and the safe-area view creates the main screen container.
- flex-1 lets the container fill the available screen space.
- bg-slate-50 gives the screen a very light gray background.
The provider itself is not a visible bar. It supplies context for the components that need it.
6. Add the top bar
<TopBar />


This renders the component from components/TopBar.js.

The self-closing syntax is appropriate because TopBar already contains its own content.
7. Add the scrollable main content
<ScrollView
  className="flex-1"
  contentContainerClassName="p-4"
>


The ScrollView occupies the remaining available space between the top and bottom bars.
- className="flex-1" allows the scroll view to expand.
- contentContainerClassName="p-4" adds padding to the inner content container.
The distinction matters: the ScrollView is the scrolling viewport, whereas its content container holds the heading, paragraph, and buttons.

Because the top and bottom bars are siblings of the scroll view, the bottom bar remains below the scrollable content rather than becoming part of that scrolling content.
8. Create the heading
<Text className="text-3xl font-bold text-slate-800">
  Hello, World!
</Text>


- text-3xl: large text.
- font-bold: bold weight.
- text-slate-800: dark slate text color.
9. Create the paragraph
<Text className="mt-2 text-base text-slate-600">
  Welcome to React Native. This is my first mobile
  application built with Expo and NativeWind.
</Text>


- mt-2 adds a top margin to separate the paragraph from the heading.
- text-base sets ordinary body-text sizing.
- text-slate-600 gives the paragraph a softer gray color.
A margin creates space outside a component. Unlike padding, it doesn't enlarge the space inside the component's border.
10. Create the primary button
<Pressable className="mt-6 items-center rounded-xl bg-indigo-600 py-3">
  <Text className="font-bold text-white">
    Get Started
  </Text>
</Pressable>


This is the filled primary button.
- mt-6: spacing above the button.
- items-center: centers the label horizontally.
- rounded-xl: rounded corners.
- bg-indigo-600: indigo background.
- py-3: vertical padding.
- font-bold text-white: bold, white button text.
Notice that Get Started is inside a Text component. You must not place the plain string directly inside Pressable.
11. Create the secondary button
<Pressable className="mt-3 items-center rounded-xl border border-indigo-600 py-3">
  <Text className="font-bold text-indigo-600">
    Learn More

Three distinctions worth remembering
1. items-center versus justify-center

These operate on different axes. In a default column layout, items-center centers horizontally, while justify-center centers vertically.

2. Padding versus margin

Padding is inside a component's edges; margin is outside. Use padding to give a button breathing room inside its background, and margin to separate it from other elements.

3. flex-1 versus flex-row

flex-1 controls how a component grows in its flex layout. flex-row changes the direction in which children are arranged. They solve different problems and are often used together.

Questions 1–2: Part C observations
1. What happens if you remove the Text tag and put "Hello, World!" directly inside the View?

The app shows an error because React Native requires text strings to be inside a Text component. A View is meant for layout and containers, not direct text rendering.

2. What does flex: 1 do to the View?

It allows the View to expand and take up the available space in its parent, which helps the content fill the screen.
Questions 3–9: Section 8
3. Name the React Native equivalents of the HTML tags div, p, img, and button.
- div → View
- p → Text
- img → Image
- button → Pressable or Button
4. Why do we need a global.css file and a tailwind.config.js file in a NativeWind project?

global.css provides the Tailwind stylesheet entry point, while tailwind.config.js tells Tailwind which files to scan and configures the NativeWind preset.

5. Why is Pressable preferred over Button when you want custom styling?

Pressable lets us style its container and text freely using className. React Native's built-in Button does not offer the same styling flexibility.

6. In your layout, what is the difference between flex-row and the default direction of a View?

flex-row arranges children horizontally, while a View uses a column layout by default and arranges its children vertically.

7. Your buttons currently do nothing. What needs to be added to make them respond when pressed?

An onPress handler needs to be added to the Pressable component. It specifies what should happen when the user presses the button.

8. In a web React project you can use div without importing it. Why must View and Text be imported in React Native, and which package provides them?

View and Text are React Native components rather than built-in HTML tags. We must import them from the react-native package before using them.

9. Why were TopBar and NavBar placed in their own files, and which two statements make it possible to use them inside App.js?

They were separated into their own files to make the code organized, reusable, and easier to maintain. export default makes each component available to other files, and import allows App.js to use them.
