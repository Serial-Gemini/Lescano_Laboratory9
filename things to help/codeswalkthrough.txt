Part 1 — Prepare your D: drive
Step 1. Create the folders
Open Command Prompt (cmd, not PowerShell) and paste this entire block:
mkdir "D:\Android"
mkdir "D:\Android\Sdk"
mkdir "D:\Android\AVD"
mkdir "D:\Android\UserHome"
mkdir "D:\Android\.gradle"
mkdir "D:\Android\npm-cache"

These commands create the folders if they don't already exist. They won't delete existing contents.

Don't create the Android Studio application folder manually. Let its installer create or use the installation directory.

Part 2 — Redirect Android's storage to D:
This is the additional setup missing from your lab manual.
Step 3. Set Windows environment variables
Press Windows + S, search for Edit environment variables for your account, and open it.

You can create the variables through the graphical window, or use the commands below in Command Prompt. Since you want everything in one go, the commands create the user variables for you.

Copy and run this block:
setx ANDROID_HOME "D:\Android\Sdk"
setx ANDROID_USER_HOME "D:\Android\UserHome"
setx ANDROID_AVD_HOME "D:\Android\AVD"
setx GRADLE_USER_HOME "D:\Android\.gradle"


What each variable does:
Variable	Purpose
ANDROID_HOME	Tells Expo and Android tools where the SDK lives.
ANDROID_USER_HOME	Redirects Android SDK tool settings to D:.
ANDROID_AVD_HOME	Redirects emulator virtual-device files to D:.
GRADLE_USER_HOME	Redirects Gradle dependencies and caches to D:.

Important: setx changes future processes, not terminals that are already open. Close Command Prompt and Android Studio, then reopen them after setting these variables.

If ANDROID_SDK_ROOT already exists in your environment variables, change it to D:\Android\Sdk or remove it if no tool requires it. Don't create conflicting SDK paths.
Step 4. Add the Android tools to Path
In the same Environment Variables window:
1. Select your user Path.
2. Click Edit → New.
3. Add this entry:
%ANDROID_HOME%\platform-tools


4. Click OK on all windows.

This lets you run adb, the Android Debug Bridge, without typing its full path.
Step 5. Redirect npm's cache
Run:
npm config set cache "D:\Android\npm-cache" --global


Verify it:
npm config get cache


Expected output:
D:\Android\npm-cache


This redirects npm's download cache. npm's small configuration file may still be stored under your Windows user profile on C:.

Step 11. Create the remaining configuration files
These are file contents, not terminal commands. In VS Code, create or edit the following files in the project root, alongside App.js and package.json.
tailwind.config.js
Replace the file's contents with:
/** @type {import('tailwindcss').Config} */
module.exports = {
  content: [
    './App.{js,jsx,ts,tsx}',
    './components/**/*.{js,jsx,ts,tsx}',
  ],
  presets: [require('nativewind/preset')],
  theme: {
    extend: {},
  },
  plugins: [],
};


global.css
Create this file in the project root:
@tailwind base;
@tailwind components;
@tailwind utilities;


babel.config.js
Replace its contents with:
module.exports = function (api) {
  api.cache(true);

  return {
    presets: [
      ['babel-preset-expo', { jsxImportSource: 'nativewind' }],
      'nativewind/babel',
    ],
  };
};


metro.config.js
Create this file in the project root:
const { getDefaultConfig } = require('expo/metro-config');
const { withNativeWind } = require('nativewind/metro');

const config = getDefaultConfig(__dirname);

module.exports = withNativeWind(config, {
  input: './global.css',
});
